# 用途
過去每次大量的工具回傳都存成完整原文，並在 system prompt 尾端的「工具使用檢索清單」留一句關聯描述（`#編號（時間）：描述`）。使用者的話是在接續、追問或延伸其中一筆時（「剛剛那些腳本挑一個」「之前查的那個馬達後來怎樣」），用這個技能：帶編號＋使用者的問題**原文**，系統重新讀那份存檔的完整原文，交給獨立 session 以這個問題為錨點提煉（有缺口會自動再查最多幾次），回給你的是提煉後的重點，你再據此回答或做下一步。不需要自己想關鍵字（那是 `result_grep`）、不需要先 `result_list` 瀏覽（清單已經告訴你是哪一筆）。清單裡沒有相關的一筆時不要用這個。

# 語法
`EXECUTE: scripts/result_recall_cmd.py <編號> "<使用者的問題原文>"`
* 編號：檢索清單裡的 `#數字`（也接受 `latest`）；編號跨 session 不重複，直接抄。
* 問題：把使用者的話原封不動放進去（可以去掉語氣詞），不要抄清單上的描述、不要改寫成關鍵字。系統會自動把使用者最新的一句話一併交給獨立 session，這個參數只是你想額外聚焦的點（例如「docker 相關的」）。
* 這個技能的語法已經寫在清單的規則裡，看到相關的一筆可以直接執行，不必先載入這份規格。

# 範例
`EXECUTE: scripts/result_recall_cmd.py 5 "隨便選一個腳本幫我做內容分析"`
`EXECUTE: scripts/result_recall_cmd.py 7 "之前那個馬達後來到底怎麼樣了"`

# 回傳
`[tool result - 任務導向摘要]` 開頭，第二行註明「重新讀取存檔 #編號（腳本，時間）的完整原文，針對「…」提煉」，其餘與工具摘要格式相同：回答／相關事實／錯誤／未涵蓋。會記軌跡、產生新的存檔編號並記進檢索清單（可以再對新編號用 `result_grep`／`result_view`）。

# 異常
* `[ERROR] 找不到結果 #N`：原始檔已超過保留上限（200 檔／50 MB）被清掉，直接告訴使用者這筆資料已不在、需要的話重新執行當時的工具；不要換個編號亂試。
* 沒有附問題內容：`[ERROR]`，補上問題原文。
